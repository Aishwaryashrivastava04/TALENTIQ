MEMBER 1 | SUBPROGRAMS

Stored Procedures: Principles & Lab Task 28

Server-side precompiled routines for executing business actions and batch updates

Concepts & Parameters
How Stored Procedures Work
  • Precompiled Performance: Compiled once into p-code and stored in data dictionary.
  • Network Optimization: Multiple SQL statements run inside DB server without roundtrips.
  • Parameter Modes: IN (read-only), OUT (returns value), IN OUT (both).
  • Security: Users get EXECUTE rights without direct table access.
-- Lab 28: Update Mumbai Commission Procedure
CREATE OR REPLACE PROCEDURE UpdateCityCommission ( p_city IN VARCHAR2, p_percent_inc IN NUMBER, p_rows_update OUT NUMBER ) IS BEGIN UPDATE Salespeople SET commission = commission * (1 + (p_percent_inc / 100)) WHERE city = p_city; p_rows_update := SQL%ROWCOUNT; COMMIT; END UpdateCityCommission; / -- Calling from SQL*Plus: VARIABLE v_count NUMBER; EXEC UpdateCityCommission('Mumbai', 10, :v_count); PRINT v_count;
MEMBER 2 | COMPUTATIONS

Database Functions: Syntax & SQL Integration

Self-contained subprograms engineered for calculation, requiring a single return value

Core Mechanics
Why Use Database Functions?
  • Mandatory RETURN: Must declare return data type and execute RETURN with single value.
  • SQL Integration: Can be called directly in SELECT, WHERE, and ORDER BY clauses.
  • Deterministic: Caches results for identical inputs to optimize performance.
  • Purity Rule: Cannot execute DML on the table being queried.
-- Function: Calculate Commission on Orders
CREATE OR REPLACE FUNCTION GetOrderCommission ( p_amt NUMBER, p_rate NUMBER DEFAULT 0.12 ) RETURN NUMBER DETERMINISTIC IS v_comm_amt NUMBER := 0; BEGIN IF p_amt IS NULL OR p_amt <= 0 THEN RETURN 0; END IF; v_comm_amt := p_amt * p_rate; RETURN ROUND(v_comm_amt, 2); -- Mandatory END GetOrderCommission; / -- Calling directly in SQL: SELECT onum, snum, amt, GetOrderCommission(amt, 0.12) AS EarnedComm FROM Orders WHERE amt > 1000;

Stored Procedure vs Database Function

Essential comparative matrix frequently tested in Amity end-term exams and vivas

Evaluation Metric Stored Procedure Database Function
Return Value Optional; Can return 0, 1, or multiple values via OUT parameters Mandatory; Must return exactly ONE value via RETURN
Call in SQL Queries Cannot be embedded inside SQL SELECT / WHERE statements Can be called directly within SELECT, WHERE, ORDER BY
DML Operations Fully permits INSERT, UPDATE, and DELETE operations Restricted when called inside SQL queries (Purity rule)

MEMBER 3 | DATA BUFFERING

Database Cursors: Context Area & 4-Step Lifecycle

Bridging set-oriented SQL with row-oriented procedural execution to process active sets

Context Area Mechanics
What is a Cursor?
  • Context Area: Private memory in SGA allocated by DB server to hold SQL query result sets.
  • Cursor Definition: Named pointer to the Context Area allowing row-by-row traversal.
  • Implicit vs Explicit: Implicit for single-row DML; Explicit for multi-row queries.
  • Attributes: %FOUND, %NOTFOUND, %ROWCOUNT, %ISOPEN.
-- Explicit Cursor: 4-Step Memory Lifecycle
DECLARE CURSOR c_orders IS SELECT onum, amt, snum FROM Orders WHERE amt > 2000; v_onum Orders.onum%TYPE; v_amt Orders.amt%TYPE; v_snum Orders.snum%TYPE; BEGIN OPEN c_orders; -- Step 1: Allocate & Execute LOOP FETCH c_orders INTO v_onum, v_amt, v_snum; -- Step 2 EXIT WHEN c_orders%NOTFOUND; DBMS_OUTPUT.PUT_LINE('Order: ' || v_onum); END LOOP; CLOSE c_orders; -- Step 3: Free Memory END; / -- Best Practice: Cursor FOR Loop auto-opens & closes FOR rec IN (SELECT onum, amt FROM Orders) LOOP ... END LOOP;
MEMBER 4 | AUTOMATION

Database Triggers: Event-Driven Programming

Autonomous PL/SQL blocks executed automatically in response to database events

ECA Model & Correlation
Architecture of a Trigger
  • The ECA Rule: Event (INSERT/UPDATE/DELETE), Condition (WHEN), Action (PL/SQL body).
  • Implicit Invocation: Cannot be called with EXEC; fires automatically upon table modification.
  • Timing & Granularity: BEFORE (validation), AFTER (auditing); Statement-Level vs Row-Level.
  • Correlation Records: :OLD (pre-update value) vs :NEW (post-update value).
  • Mutating Table: ORA-04091 warning when row trigger queries the same table.
-- Trigger: Commission Audit Log on Salespeople
CREATE OR REPLACE TRIGGER Trg_AuditSalesCommission AFTER UPDATE OF commission ON Salespeople FOR EACH ROW BEGIN IF :OLD.commission != :NEW.commission THEN INSERT INTO Comm_Audit_Log ( snum, old_comm, new_comm, changed_by, change_date ) VALUES ( :OLD.snum, :OLD.commission, :NEW.commission, USER, SYSDATE ); END IF; END Trg_AuditSalesCommission; /
MEMBER 5 | RESILIENCE

Exception Handling: Fault-Tolerance & Taxonomy

Preventing runtime crashes, ensuring data integrity, and isolating error recovery

Taxonomy & Diagnostics
Architecture & Diagnostic Tools
  • Why Handle Exceptions? Separates business code from error recovery; ensures clean ROLLBACK.
  • Pre-Defined System: NO_DATA_FOUND, TOO_MANY_ROWS, ZERO_DIVIDE.
  • User-Defined: Declared via e_name EXCEPTION, triggered via RAISE.
  • Diagnostics: SQLCODE (numeric code) and SQLERRM (text message string).
-- Enforcing commission threshold with exception handling
DECLARE v_comm Salespeople.commission%TYPE; e_excess_comm EXCEPTION; -- Custom Exception BEGIN SELECT commission INTO v_comm FROM Salespeople WHERE snum = 1001; IF v_comm > 0.25 THEN RAISE e_excess_comm; -- Explicit raise END IF; EXCEPTION WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('Salesperson not found.'); ROLLBACK; WHEN e_excess_comm THEN RAISE_APPLICATION_ERROR(-20002, 'Commission exceeds 25% cap!'); WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('Error: ' || SQLCODE || ' - ' || SQLERRM); ROLLBACK; END; /

CSIT661 End-Term & Viva Voce Cross-Questions:

Q: Procedure vs Function? ➔ Procedure executes actions/DML; Function calculates and MUST return exactly one value.

Q: Why close an explicit cursor? ➔ Releases Context Area memory and prevents ORA-01000 limit.

Q: What is a Mutating Table error? ➔ ORA-04091: Row trigger modifying/querying table currently undergoing DML.

Q: Difference between :OLD and :NEW? ➔ :OLD holds pre-update values; :NEW holds incoming update values.

Q: Purpose of SQLCODE and SQLERRM? ➔ SQLCODE returns numeric error code; SQLERRM returns the textual error message.
